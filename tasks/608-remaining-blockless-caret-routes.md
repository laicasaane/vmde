## Execution progress — 2026-10-14 (S2c)

The contract's fallback is now implemented, triggered by the keyboard root landing S2 measured (ArrowRight out of the boundary-0 gap).

- **Repair.** `media-src/src/editing/editor-caret.ts` (`installIrMarkerReveal`): a trusted navigation keydown (arrows, Home, End, PageUp, PageDown) aimed at the IR editor arms the next frame for 250 ms. If that frame finds a collapsed range on the bare editable root, with at least one `data-block` child and no live caret intent, the key's direction picks the landing. Forward: skip void blocks (rule, non-editable TOC) and enter the next text block at its first content position, after any heading marker. Backward: land at the end of the previous text block, or in the boundary-0 gap when the walk reaches the start of the document. Two atomic blocks side by side get the gap between them. Forward off the end of the document, code blocks, tables and other blocks that hold their own caret are left to the native move. The write is one-shot (the caret intent is retired at once), and the repaired range then goes through the existing marker normalization. `gap-nav.ts` only exports `placeCaretInGap`.
- **Not normalized.** A programmatic collapsed root range (no keydown), an untrusted key, a key during composition or while composition is active, a stale key (older than the window), a live caret intent, and the empty editor (no `data-block` child).

M4 Ctrl+End on an HR-last document passed before and after: the trailing paragraph (wired into the harness as in the product) takes the caret, so no fix is needed there.
